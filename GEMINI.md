# GEMINI.md - Instructional Context

This file provides architectural context and operational guidelines for the **Wythoff's Game** project. Use this as a reference for future modifications and development tasks.

## Project Overview
A modern, browser-based implementation of **Wythoff's Game** featuring:
-   **Core Logic:** Mathematical game logic and a "Perfect AI" written in Rust and compiled to WebAssembly.
-   **Frontend:** A responsive, mobile-first UI built with Vite and Vanilla JavaScript.
-   **Multiplayer:** Real-time, serverless P2P multiplayer powered by PeerJS (WebRTC).
-   **State Management:** Persistence and shareable game sessions via URL hash synchronization.

## Architecture & Technology Stack
-   **Rust & Wasm (`wythoff-wasm/`):**
    -   Uses the Beatty Sequence ($\lfloor n\phi \rfloor$, $\lfloor n\phi^2 \rfloor$) to determine "Cold Positions".
    -   Exports `init_game`, `validate_move`, and `ai_move` via `wasm-bindgen`.
-   **Vite & JavaScript (`src/`, `index.html`):**
    -   Orchestrates game modes (`MENU`, `VS_COMPUTER`, `MULTIPLAYER`).
    -   Manages P2P connections and state handshakes.
    -   Handles dynamic token rendering and accessibility (ARIA).
-   **Styling (`src/style.css`):**
    -   Dark-themed, responsive design with "Turn Glow" visual feedback and CSS-based toast notifications.

## Key Files & Directories
-   `wythoff-wasm/src/lib.rs`: The "Brain" - holds all game rules and AI strategies.
-   `src/main.js`: The "Orchestrator" - handles UI events, networking, and state sync.
-   `pkg/`: The compiled Wasm binary and JS glue code (generated by `wasm-pack`).
-   `CODEBASE_GUIDE.md`: A high-level technical map of the project components.

## Building and Running
### Build the Wasm Module
```bash
cd wythoff-wasm && wasm-pack build --target web --out-dir ../pkg
```
### Run Development Server
```bash
npm run dev
```
### Build for Production
```bash
npm run build
```

## Development Conventions
-   **State Isolation:** Maintain strict separation between `VS_COMPUTER` and `MULTIPLAYER` UI elements.
-   **URL Priority:** Always check `window.location.hash` on load before randomizing game state.
-   **Non-Blocking UI:** Use the custom toast system ( `showToast()` ) instead of `alert()` to avoid blocking the main thread or breaking PeerJS connections.
-   **Performance:** Cap visual token rendering at 100 tokens to ensure smooth performance on low-end mobile devices.

## Maintenance Notes
-   If you modify Rust logic, you **must** rebuild the `pkg/` directory for changes to reflect in the frontend.
-   Multiplayer testing requires two browser instances (can be two tabs on the same machine).
